### Bootstrap artifacts (the pinned-download source)

- Published as GitHub release assets on `termux/termux-packages`, tags of the form
  `bootstrap-YYYY.MM.DDrN+apt.android-7`, regenerated weekly by
  `scripts/bootstrap_archives.yml`.
- Assets per release: `bootstrap-aarch64.zip`, `bootstrap-arm.zip`,
  `bootstrap-i686.zip`, `bootstrap-x86_64.zip` (~25–29 MB each) plus
  `CHECKSUMS-md5.txt`, `CHECKSUMS-sha256.txt`, `CHECKSUMS-sha512.txt`.
- Archives contain entries **relative to `$PREFIX`**, plus `SYMLINKS.txt`
  (`target←name` lines) instead of real symlinks; executables are chmodded by the
  installer. Second-stage scripts run apt/pacman setup on first boot.
- Generated by `scripts/generate-bootstraps.sh`, which downloads prebuilt `.deb`
  packages from the Termux repository and repacks them.

## 2. Hard constraints discovered

### C1 — Packages are compiled for a fixed prefix

Termux packages are compiled for `/data/data/com.termux/files/usr`. Upstream states
plainly that these packages "would not work for any other app package name or a
different app data or rootfs directory, and packages must be compiled specifically for
any such changes" (wiki: Termux execution environment). The maintainers also rejected
making the prefix relocatable — every package would have to be audited for hardcoded
paths — and note the fixed prefix deliberately binds the packages to `com.termux`
(maintainer reply, termux-app#2291).

Consequences for PocketDev (package `dev.pocketdev`, data dir `/data/data/dev.pocketdev`):

- Compiled-in prefixes exist in binaries *and* scripts (Python's `sys.prefix`, apt
  config files, dpkg's file database, shebangs).
- Text-level paths can be rewritten during extraction; binary strings cannot.
- Rewriting file access at runtime (LD_PRELOAD intercepting `exec*`, `open*`,
  `stat*`, `realpath`, …) is the only relocation approach that does not require
  rebuilding packages. Upstream designed exactly this ("dynamic variables",
  termux-packages#24407, NLnet-funded work; status as of 2025-06: "a few months
  away", unverified since).

### C2 — Android 10+ W^X blocks exec from app data for targetSdk ≥ 29

Apps targeting API 29+ cannot `execve()` files inside their own data directory
(Android 10 behavior change; SELinux `untrusted_app_29+` keeps `execute` but drops
`execute_no_trans`). Termux itself ships with **targetSdk 28** for this reason and
left Google Play over it.

Workarounds available to PocketDev (which keeps targetSdk 36):

1. **System linker trick**: `/system/bin/linker64 /path/to/elf` is allowed on
   Android ≥ 10 (the kernel only sees `linker64` executing); the linker then maps
   the app-data ELF. `termux-exec` implements this inside its `exec*` interception.
2. First hop from Java must therefore invoke `linker64` explicitly; every later hop
   is handled once `LD_PRELOAD=$PREFIX/lib/libtermux-exec.so` is in the child
   environment.
3. Static binaries cannot run this way (rare in Termux); raw `execve` syscalls bypass
   the hook (rare).

**Open question for Milestone 3:** prove the linker64 + `LD_PRELOAD` chain end-to-end
on a targetSdk 36 app in CI. This is the single largest technical risk to the runtime.

### C3 — Bootstrap zip layout is prefix-relative (good) but content is not

Extraction target is our choice, so `<dataDir>/files/usr` works as `$PREFIX`. What
breaks under relocation is everything *inside* the payload that embeds
`/data/data/com.termux` (see C1). The `SYMLINKS.txt` mechanism and chmod rules must
be reproduced by our extractor (prompt §8.4).

### C4 — Upstream mirror policy

Upstream describes the hardcoded prefix partly as protection against third parties
serving their packages to other app ids (termux-app#2291). Depending on
`packages.termux.dev` from a non-`com.termux` app is therefore against upstream
intent even if technically possible. Any `apt install` strategy needs either upstream
blessing, a rebuilt repository of our own, or explicit product-owner approval.

### C5 — Primary user / storage paths

Termux refuses non-primary-user installs because expected paths differ. Our data dir
path must stay the legacy `/data/data/dev.pocketdev` form (not `/data/user/0/...`)
for path-rewrite rules to be simple; adoptable storage (`/mnt/expand/...`) is out of
scope initially and must be detected and rejected.

## 3. What PocketDev will not do

- No separate Termux APK, no fork of the full Termux app (prompt §4, §8.2).
- No PRoot/chroot/fake-Linux layer (prompt §1, §4).
- No building or testing on the owner's phone (prompt §0.1, §5).
- No copying of GPLv3 `termux-shared` files unless the license decision explicitly
  accepts GPLv3 for the combined work.
- No bundling of bootstrap binaries inside the APK (download + checksum-verify at
  first run instead; prompt §8.4).
